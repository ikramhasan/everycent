5b

Transfers between accounts

Done · 875153a

Picking "Transfer : Savings" in Checking creates a linked pair of transactions, one in each account, following YNAB's rules for budget and tracking accounts.

What shipped

  • A "Transfer : <account>" payee for every account, renamed with it. Fresh start creates them for the new accounts.
  • Both sides point at each other. Date and amount sync; memo, cleared and category stay per side.
  • Pointing a transfer at another account moves the other side. A normal payee turns it back into a normal transaction. Deleting either side deletes both.
  • Only the budget side of a transfer to a tracking account has a category.
  • Register: a "Transfers" group in the payee picker, and a ⇆ icon that jumps to the other side and highlights it.
  • The payee cell opens the full list with the current payee selected, as YNAB does; Enter without picking keeps it.

Settled

  • No new transfers to or from closed accounts. Existing ones stay editable.
  • If the other side is reconciled, the date and amount can't change, and the transfer can't be deleted or pointed elsewhere. Phase 9's unlock flow takes over.
  • The close-account dialog is unchanged. "Transfer the balance to…" is in deferred.md.
  • Deleting an account with transfers is blocked: it has history, so it gets closed instead.

Cleared from deferred.md: transfer payees. Added follow-ups for credit card payments (Phase 7), reconciled sides (Phase 9), cross-currency rates (Phase 11) and split transfers (5c).

5c

Split transactions

Done · phase-5c-splits

One transaction spread across several categories, like a supermarket receipt that covers groceries and household items. A split line can also be a transfer.

What shipped

  • sub_transaction table: amount, category, memo, optional payee; a transfer line's other side points back with transfer_sub_transaction_id.
  • The API rejects lines that don't add up (SPLIT_TOTAL_MISMATCH), splits in tracking accounts and split transfers.
  • "Split" at the end of the category picker opens line editing with a "left to split" counter; the current category moves to the first line.
  • Split rows read "Split (n categories)" with their lines underneath; clicking either opens the whole split.
  • A transfer line keeps a linked transaction in the other account, moving with the split's date, amount and account.
  • Category history and delete-with-reassign include split lines. Payee "last category" skips splits.

Settled

  • A split always opens as a full editor, as in YNAB.
  • Removing lines down to one un-splits it, keeping that line's category (or transfer).
  • The other side of a transfer line only edits memo, cleared and category; the rest goes through the split (TRANSFER_IN_SPLIT).

Cleared from deferred.md: split transfers. Added follow-ups for reconciled transfer lines (Phase 9) and category activity from split lines (Phase 6).

5d

Flags

Done · phase-5d-flags

YNAB's six flag colors on any transaction, with names you choose per budget (for example red = "Reimbursable").

What shipped

  • flag column on transactions (red, orange, yellow, green, blue, purple or none), set on create and edit.
  • flag_name table and GET/PUT /v1/budgets/{id}/flags; an empty name clears it.
  • Flag cell before the date, as in YNAB: a bookmark in the flag's color, opening the six colors, "Clear flag" and "Edit names".
  • Fresh start copies the flag names.

Settled

  • Flag names belong to the budget, so partners see the same names (as in YNAB). Anyone who can edit transactions can rename them.
  • A transfer's flag is per side, like memo and cleared.
5e

Sort, search and filter

Next

Finding things in a long register: click a column header to sort, type to search, and narrow by date range and state.

Scope

  • Sort by date, payee, category, memo, amount, cleared (TanStack Table sorting).
  • Search box matching payee, category, memo and amounts (typing 45.10 finds that amount).
  • Filters: date range (this month, last 3 months, year to date, custom), cleared state, flag, category, payee.
  • Running balance hides while sorted by anything other than date, as YNAB does.
  • The filter state is kept in the URL so a filtered register can be bookmarked.

To settle first

  • Filter on the server or in the browser? Browser is simpler while registers fit in one response; the server is needed once paging exists (see deferred.md).
  • Default view: everything, or YNAB's "this year" date range?

Done when searching "costco", filtering to uncleared, and sorting by amount all work together and survive a page reload.

5f

Multi-select and bulk edit

Needs 5d

Select several transactions and change them at once, the way YNAB's toolbar does after ticking rows.

Scope

  • Checkbox column with shift-click range select and "select all" for the current filter.
  • Toolbar actions: categorize, change payee, change date, flag, mark cleared or uncleared, move to account, delete.
  • One API call per action that applies to all selected transactions in one database transaction.
  • Totals of the selection shown in the toolbar.

Rules

  • Moving to another account follows the category rules from 5a and the transfer rules from 5b.
  • Transfer pairs and split lines move or delete together.
  • Bulk delete asks for confirmation inside the page.

Done when twenty transactions can be selected, recategorized and cleared in two clicks, and the edit is atomic: either all change or none.
