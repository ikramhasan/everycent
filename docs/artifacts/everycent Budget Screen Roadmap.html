Build sequence for the budget screen

Phase 5 built the register; Phase 6 turns it into a budget. Its fifteen README items are split into six stages, built in dependency order, after closing out Phase 5. Each stage gets its own branch, stacked on the one before; all of Phase 6 is merged into main at once when it's done. YNAB behaviour that can't be checked goes to docs/verify.md.

Ground rules

  • Match YNAB one to one; check, don't assume. When unsure how YNAB behaves, try it in YNAB's web app with the Chrome tool (a test account is signed in). Anything the app can't settle is skipped and listed in docs/verify.md.
  • Money is never a float. Assigned amounts are bigint minor units with a currency, like every other amount.
  • The server does the math. Activity, available and Ready to Assign are computed by the API, as the register's balances are.
  • One branch per stage, one merge for the phase. Each stage is built on a branch stacked on the last, checked in the browser in both themes, and committed with pnpm check passing; Phase 6 is merged into main as a whole.
